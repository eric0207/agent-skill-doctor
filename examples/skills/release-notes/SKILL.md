# Release notes

## Workflow

1. Read the supplied change summary.
2. Group changes into features, fixes, and breaking changes.
3. Write concise notes for end users.
4. Do not claim changes that are not present in the supplied summary.

See [the style guide](references/style-guide.md) for wording conventions.
